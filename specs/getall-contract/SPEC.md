# SPEC — GetAll() Container Contract

**Status:** DRAFT (cycle-2 synthesis, 2026-07-20)
**Feature slug:** `getall-contract`
**Owner:** LEX crew (lex-lead synthesis)

## 1. Problem

`project.<Entity>.GetAll()` in flexicon 4.2.1 does not have a single container
shape, and the guidance/index/validator surfaces disagree about what it returns.
Generated scripts therefore adopt unsafe idioms — `len(GetAll())`, subscript
`GetAll()[0]`, truthiness `if not GetAll()`, and double-consume — that work for
some entities and silently break (or degrade) for others.

Two Cycle-1 scoping passes established the facts (verbatim inventories in
`reviews/cycle1-explore.md` and `reviews/cycle1-lex-domain.md`):

- **17 unsafe idiom sites** across templates, docs, CLAUDE.md, curated recipes,
  worked examples, the `common_patterns` JSON, and the eval corpus.
- **Defect A (CONFIRMED):** 10 flexicon GetAll methods carry prose that claims the
  result is *"an EnumerableWrapper (subscriptable, len()-able, lazily
  materialized)"* while `output_behavior.success.type` names only the **per-yield
  element** interface (e.g. `ILexEntry`). Prose describes the container;
  `returns.type` describes the element. Same shape 10x.
- **Silent gap (23 methods):** `returns.type` is a bare element interface (or
  `dict`) with **zero** container-shape language — including `LexSenseOperations`.
  No keyword to contradict; the *absence* of container info is the tell.

## 2. Container-shape taxonomy (51 flexicon GetAll methods)

| Shape | Count | What it returns | `len()`/subscript/repeat-iterate | `list(...)` idiom |
|-------|-------|-----------------|----------------------------------|-------------------|
| (a) Python `list` | 16 | real list | safe | safe but redundant |
| (b) Smart collection | 2 | `AllomorphCollection`, `RuleCollection` | safe | **capability-losing** — see §4 |
| (c) `EnumerableWrapper` | 33 | lazily-materialized wrapper that may degrade to a one-shot generator/IEnumerable | **UNSAFE** | safe & correct (its purpose) |

The **(c) set of 33 is the unsafe set**: 10 "strong" self-contradictory
(LexEntry, Text, Wordform, Person, Media, Paragraph, WfiGloss, ScrBook, ScrDraft,
ConstChart) + 23 "silent" element-type-only (incl. LexSense, POS, Segment,
Reversal*, etc.). Full membership: `reviews/cycle1-lex-domain.md` §1.

## 3. Canonical `returns.type` wording (Level 2 target)

Always describe the **container**, never the element:

- (a) `list[<IElement>]` — e.g. `list[ILexEntry]`; deprecate bare `list`.
- (b) `<CollectionClass>[<IElement>]` — e.g. `AllomorphCollection[IMoForm]`,
  `RuleCollection[IPhRegularRule]`.
- (c) `EnumerableWrapper[<IElement>]` — e.g. `EnumerableWrapper[ILexEntry]`. This
  single change fixes all 10 strong contradictions and closes the 23 silent gaps
  by forcing an explicit container declaration.

## 4. Safe materialization idiom & the (b) caveat

`list(project.<Entity>.GetAll())` is the recommended universal fix when a script
needs `len()`, subscript, or repeat iteration:

- (c): safe & correct.
- (a): safe, redundant shallow copy.
- (b): **never crashes but is capability-losing** — `list()` discards
  `.filter()`, `.regular_rules()`, and the type-breakdown `__str__`. Validator
  guidance must treat (b) distinctly: keep the collection and use its methods, or
  only `list()` it when those capabilities are genuinely unneeded.

## 5. Scope decisions (lex-lead)

- **The contract is flexicon-specific.** Cycle-1 Explore flagged
  `15_ok_flexlibs_stable_mode.yaml` (api_mode `flexlibs_stable`) as a required
  flip. **Overruled.** The stable index (`flexlibs_api_v1.2.8.json`) is
  function-based and has no `Operations.GetAll` returning an EnumerableWrapper; the
  EnumerableWrapper hazard is a flexicon-4.2.1 concept. The Level-3 validator rule
  and the corpus flips are **api_mode == flexicon only**. Case 15 stays `ok`.
- **Corpus flips = 2, not 3.** Only `issue20_import_satisfies_discovery.yaml` and
  `issue41_parenthesized_multiimport_ok.yaml` (both api_mode `flexicon`,
  currently `outcome: ok`) flip to expect the new advisory. The three
  already-`reject` cases (10, 11, 18) keep their outcome; their idiom snippets are
  corrected for hygiene only (no outcome change).
- **Wrong factual claims must be deleted, not just reworded:**
  `curated_recipes.py:444` and the mirroring `common_patterns` JSON comment
  assert "GetAll returns an EnumerableWrapper that supports len()" — false for the
  contract. Replace with the `list(...)` idiom.
- **Index layer question (for lex-programmer to resolve):** confirm whether
  `common_patterns_flexicon-v4.2.1.json` and `flexicon_api_v4.2.1.json` are

- **Out of scope:** raw API-reference docstring subscript hits, internal

  generated scripts.

## 6. The three-level fix

### Level 1 — Mechanical idiom fix (guidance surfaces + corpus)
Replace unsafe idioms with `list(GetAll())` (shape-c) or shape-appropriate
guidance at all 17 sites (inventory: `reviews/cycle1-explore.md`). Delete the two
false "supports len()" claims. Flip the 2 flexicon-mode corpus `ok` cases; correct
(without outcome change) the 3 `reject` cases' snippets.

### Level 2 — Index `returns.type` reconciliation
Apply §3 canonical wording to all 51 flexicon GetAll methods: 16 → `list[X]`,
2 → `Collection[X]`, 33 → `EnumerableWrapper[X]`. Remove the element-only leak.
Land at the correct layer per §5 so refresh is idempotent.

### Level 3 — Validator rule (flexicon mode only)
New detector in `src/flextoolsmcp/server/validators.py` that flags the unsafe
idioms (`len`, subscript, truthiness, double-consume) on a GetAll result whose
resolved shape is (c). Prefer keying off the reconciled Level-2 `returns.type`
shape (`EnumerableWrapper[...]` = warn, `list[...]` = ok, `<Collection>[...]` =
(b)-caveat) rather than a hardcoded 33-name set, so the rule stays correct as the
API evolves. Emit `list(...)` guidance for (c) and the capability-loss caveat for
(b). Wire into the execution pipeline (`handlers/execution.py`, alongside
`detect_invalid_project_chains` / `detect_undiscovered_entities`).

## 7. Success criteria / gates

- All 17 idiom sites corrected; both false claims deleted.
- All 51 GetAll `returns.type` values use container wording (§3); `refresh.py`
  reproduces them.
- Validator flags (c)-shape unsafe idioms in flexicon mode, is silent for
  shape (a), and gives the (b) capability-loss caveat; no false positive on plain
  `for x in GetAll():` iteration or single-pass `next(...)`.
- Corpus: issue20 + issue41 flip and pass; case 15 unchanged; 10/11/18 unchanged.
- Full test suite green; new detector has direct unit tests.
